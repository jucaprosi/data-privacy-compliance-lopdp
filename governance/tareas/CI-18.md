# CI-18 · Una sola comprobación antes del corte a Cloud SQL

**Origen.** Revisión del #453 (CI-17) del 2026-11-07: sin Neon, el CI ya no compara la revisión de una base remota y `scripts/verificar_revision_alembic.py` quedó sin uso en el CI. Pero el paso 5 de la guía de GCP-04 y la parte B del brief del propietario lo usaban antes del corte. **Decisión del CTO con el Arquitecto (2026-11-08):** la comprobación de Alembic pasa a `verificar_cloudsql_conexion.py` y el script viejo se borra.

## Entrega
- `scripts/verificar_cloudsql_conexion.py` suma la **comprobación 5**: `alembic current` coincide con `alembic heads`.
  - Lee solo `CLOUDSQL_DATABASE_URL`, sin respaldo a `DATABASE_URL`.
  - Salida: 0 si todo está bien; 1 si la base está atrasada o alguna comprobación falla; 2 si falta la variable o la configuración.
  - Nunca imprime la URL ni partes de ella.
- Se borra `scripts/verificar_revision_alembic.py`, con sus pruebas de lectura y de «no imprime la conexión».
- En `tests/test_verificar_revision_alembic.py` **se conservan** las guardias del workflow: migrar sin `if`, sin secretos y con URL solo local, junto con su tabla de mutaciones. Si el archivo queda solo con ellas, se renombra a `tests/test_ci_migrar_contenedor.py` y se actualiza esta propiedad.
- `tests/test_seleccionar_pruebas.py` deja de usar el script como caso de ejemplo y usa otro que exista.
- `governance/operaciones/MIGRACION_CLOUDSQL_POSTGRES.md`, paso 5, y la parte B del brief del propietario quedan con **un solo comando**: `python scripts/verificar_cloudsql_conexion.py`.

## Pruebas (`tests/test_gcp04_cloudsql_migration_cutover.py`)
1. Base en la cabeza: código 0.
2. Base atrasada: código 1.
3. Sin `CLOUDSQL_DATABASE_URL` (aunque `DATABASE_URL` exista): código 2.
4. La URL simulada no aparece en la salida ni en los errores.

**Mutación:** quitar la comprobación 5 hace fallar la prueba 2.

## No hagas
- No tocar `.github/workflows/`.
- No conectarte a ninguna base real: solo valores simulados.
