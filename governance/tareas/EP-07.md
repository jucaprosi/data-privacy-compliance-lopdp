# EP-07 · Verificador del entorno de pruebas

**Contrato:** `PRD_EVYDENTIA_REVENTA_NUBE.md` §5.5 («Interfaz pública que comparten las tareas») e invariante 57. Se programa contra esa interfaz, no contra el código de `EP-01`, y se prueba con un servidor HTTP falso.

## Entrega
- `scripts/verificar_entorno_pruebas.py <frontend> [<backend>]`: devuelve código 0 solo si se cumple todo lo siguiente:
  - `/api/v1/health` está sano; reutiliza `scripts/verificar_despliegue.py` importándolo, sin modificarlo;
  - `/api/v1/entorno` devuelve `entorno = "pruebas"` y `datos_ficticios = true`, con `X-Entorno: pruebas`;
  - una ruta con datos de organización, llamada con `X-Tenant-ID` y `X-User-ID` y sin token, responde 401, lo que demuestra que el modo `headers` no está activo;
  - sin la identidad de IAP, el frontend no es accesible;
  - `robots.txt` contiene `Disallow: /`;
  - imprime el digest de la revisión que sirve, para `scripts/digest_verificado.py` (`EP-06`).

  Atraviesa IAP con un token de identidad de una cuenta de servicio autorizada, obtenido con las credenciales por defecto de Google, y nunca lo imprime.
- `governance/apoyo/BRIEF_PROPIETARIO_EP07_WORKFLOW.md` (decisión del CTO, 2026-11-08): el brief con el contenido de `.github/workflows/entorno-pruebas.yml` para que lo aplique el propietario; el sub chat no escribe en `.github/`. El workflow se dispara con `workflow_dispatch` y al terminar el despliegue en pruebas. Se autentica en Google Cloud por *Workload Identity Federation*, sin claves de cuenta de servicio en GitHub. No es un check obligatorio de `main`. Las direcciones salen de variables del repositorio, no del archivo. Es gobernanza reservada: lo aplica el propietario.
- `governance/operaciones/ENTORNO_DE_PRUEBAS.md#EP-07`: comando pegable y cómo leer cada fallo.
- Pruebas: con el servidor falso, cada comprobación falla por su propia causa, y ni el token ni la URL aparecen en la salida.

## No hagas
- No tocar `.github/workflows/zero-regression-pipeline.yml` (`CI-17`) ni `scripts/verificar_despliegue.py`.
