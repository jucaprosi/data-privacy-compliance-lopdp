# EP-05 · Verificador del entorno de pruebas

**Contrato:** PRD §7.2 («Interfaz pública que comparten las tareas»). Se programa contra esa interfaz, no contra el código de EP-01, y se prueba con un servidor HTTP falso.

## Entrega
- `scripts/verificar_entorno_pruebas.py <backend> <frontend>`, código 0 solo si todo se cumple:
  - `/api/v1/health` sano (reutiliza `scripts/verificar_despliegue.py` importándolo, sin modificarlo);
  - `/api/v1/entorno` devuelve `entorno = "pruebas"` y `datos_ficticios = true`, con `X-Entorno: pruebas`;
  - una ruta con datos de organización, llamada con cabeceras `X-Tenant-ID` y `X-User-ID` y sin token, responde 401: demuestra que el modo `headers` no está activo;
  - el frontend responde y su `robots.txt` contiene `Disallow: /`.
  Si existe `VERCEL_AUTOMATION_BYPASS_SECRET`, la envía en `x-vercel-protection-bypass` (decisión 1 del PRD §7.2, opción B); nunca la imprime.
- `.github/workflows/entorno-pruebas.yml`: se dispara con `deployment_status` exitoso de la rama `preview/pruebas` y con `workflow_dispatch`; corre el verificador y no es un check obligatorio de `main`. Las direcciones vienen de variables del repositorio, no del archivo.
- `governance/operaciones/ENTORNO_DE_PRUEBAS.md#EP-05`: comando pegable y lectura de cada fallo.
- Pruebas: cada comprobación falla por su causa con el servidor falso; el secreto no aparece en la salida; el flujo solo reacciona a `preview/pruebas`.

## No hagas
- No tocar `.github/workflows/zero-regression-pipeline.yml` (CI-14) ni `scripts/verificar_despliegue.py`.
