# QA-05 · Cero filas pendientes en la matriz de permisos

**Objetivo.** El criterio 10 del MVP dice que ninguna fila de `tests/test_matriz_permisos.py` queda pendiente. Hoy se cumple de hecho (205 passed, 0 xfailed contra PostgreSQL, 2026-10-22), pero la prueba marca los endpoints no registrados como `xfail(strict=False)`: si mañana una fila dejara de tener endpoint, la suite seguiría en verde. El árbitro no protege el criterio.

## Entrega
- En `tests/test_matriz_permisos.py`, un endpoint de la matriz que no esté registrado en la aplicación **hace fallar la prueba** con un mensaje que nombra el método y la ruta; se retira el `xfail` dinámico.
- Una prueba adicional que recorre las rutas registradas de la API bajo los prefijos que cubre la matriz (`/api/v1/roadmaps`, `/api/v1/organizacion`, `/api/v1/areas`) y falla si alguna **no está en la matriz**, salvo una lista `FUERA_DE_MATRIZ` declarada con motivo (por ejemplo, rutas sin control por rol). Así la matriz no se queda atrás cuando se añade un endpoint.
- **Prueba de mutación documentada:** añadir a la matriz una fila con una ruta inexistente y comprobar que la prueba falla; quitar una fila existente y comprobar que la prueba de cobertura falla.

## Límites
- No cambia los permisos de ningún endpoint: si al endurecer aparece una discrepancia real entre la matriz y el código, se informa al coordinador (es una decisión de producto, PRD §5.2) y no se corrige en esta tarea.
