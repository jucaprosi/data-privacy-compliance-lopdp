# CI-03 · Playwright sin repetir commit

**Objetivo.** Ahorrar de 7 a 9 min por cada PR que reutiliza la corrida de su push; hoy Pytest se reutiliza y Playwright no.

## Entrega
- `Playwright Frontend` no corre si la corrida está cubierta, y solo se adopta una corrida cuyo Playwright pasó.
- `resultado_del_arnes`, en `scripts/corrida_cubierta.py`, exige también el Playwright del push: hoy solo mira los arneses, y con Playwright omitido un fallo en el push quedaría adoptado.
- Una prueba del flujo fija esa condición.

## No hagas
- No cambiar la lista de checks obligatorios de `main`.

## Hecho cuando
Un Playwright fallido en el push no se adopta, y los PR de `tarea/` ejecutan Playwright una sola vez. Reformulado el 2026-11-02 por el coordinador: la redacción original pedía un PR real cubierto con Playwright omitido, que el flujo actual no produce (ver «Estado»).

## Estado

Integrada en #320. Se cierra con el árbitro reformulado, porque el original no se podía cumplir con las ramas de hoy: la adopción exige que la base del PR sea ancestro de su cabeza (`dev/jose` y `dev/aleczandra` no lo son de `dev/juan-carlos`), los PR hacia `main` no adoptan por diseño (`CI-02`), los de `tarea/` no tienen push que adoptar y no hay ningún PR de `dev/*` hacia `dev/*` en el historial. La regla del repositorio rechazó además crear una rama `dev/` temporal. Se decidió no añadir `tarea/**` a `on.push`.

Evidencia con datos reales de GitHub Actions (`scripts/corrida_cubierta.py` de `520980f`, sin Neon, con una corrida actual inventada):
- `520980f` con la corrida de push 41561619277 (Playwright en verde): «cubierta por la corrida 41561619277 del push, que ya verificó este commit».
- `7015a99` con la corrida de push 41066562996 (`Playwright Frontend: failure`): «terminó sin éxito (Playwright Frontend: failure); el PR corre su arnés». Es la única de las 42 corridas de push de `dev/juan-carlos` revisadas con Playwright fallido.
- Los PR de `tarea/` posteriores a #320 ejecutan Playwright una vez: 41533574219 y 41560579642.

**Riesgo aceptado, sin observar en una corrida real:** que un PR cubierto omita `Playwright Frontend` y el check obligatorio quede aprobado. Solo lo fija la prueba del flujo y no se consultó la lista de checks de `main`. Tampoco existe una corrida real con el arnés en verde y Playwright en rojo; ese caso exacto lo cubren solo las pruebas unitarias. Si el flujo llega a producir un PR `dev/*` → `dev/*` con la base al día, la primera corrida debe revisarse a mano. El ahorro de 7 a 9 min por PR no aplica al flujo actual.
