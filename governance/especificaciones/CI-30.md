# CI-30 · Autodescubrimiento en playwright.config.ts y arnés de Playwright por salas en CI
`¤ci-cd` `¤arbitro`

## 1. Datos

Sin cambios en esquema ni base de datos. Modifica cómo se descubren y ejecutan los archivos de prueba de interfaz:

- `frontend/playwright.config.ts`: la constante `SOLO_DESARROLLO` pasa de lista manual a autodescubrimiento sincrónico en tiempo de carga (`descubrirSoloDesarrollo(dirTests)`).
- `scripts/seleccionar_pruebas.py`: incorpora `MAPA_SALAS_PLAYWRIGHT` y `calcular_specs_playwright`, produciendo `playwright_specs` para `$GITHUB_OUTPUT`.
- `.github/workflows/zero-regression-pipeline.yml`: el step de pruebas de Playwright ejecuta únicamente los specs calculados y se omite si la lista queda vacía.

## 2. API

No aplica.

## 3. Reglas

- **R1 · Autodescubrimiento sin acoplamiento.** Todo archivo `.spec.ts` en `frontend/tests/` que omite el proyecto `produccion` (`test.skip(x.project.name === "produccion")`) o que invoca utilidades de entorno de desarrollo (`fijarAjustes`, `__LOPDP_AUTH_PRUEBAS__`, `harness-roadmap`) o convención `*-activa.spec.ts` se incluye automáticamente en `SOLO_DESARROLLO`. Ninguna tarea futura requiere editar `playwright.config.ts` para registrar sus pruebas.
- **R2 · Ejecución E2E por sala afectada.** Un PR cuyos cambios tocan exclusivamente una o más salas de negocio ejecuta solo los specs de interfaz de esas salas (`tests/<sala>`).
- **R3 · Cobertura completa ante cambios compartidos.** Si un cambio toca componentes de armazón (`frontend/src/components/layout/`, `frontend/src/app/`, librerías centrales o configuración), la suite de Playwright ejecuta `tests/` completa. Lo mismo ocurre en corridas sin base o hacia `main`.
- **R4 · Omisión segura en backend y gobernanza.** Si un cambio afecta exclusivamente a lógica de backend sin UI o gobernanza/documentación, `playwright_specs` es cadena vacía, y el job `playwright` termina de inmediato sin ejecutar pruebas redundantes ni descargar Chromium.
- **R5 · Preservación de CI-16.** Toda prueba que se salte en producción sigue corriendo en el proyecto `desarrollo`. `test_ci16_pruebas_sin_proyecto.py` verifica que no existan especificaciones huérfanas.

## 4. Interfaz

No aplica cambios visuales de usuario final. Optimiza los tiempos de retroalimentación de interfaz en CI de 12 minutos a ~45 segundos para PRs de sala y ~2 segundos para PRs de backend puro.

## 5. Aceptación

| Escenario | Prueba |
| :--- | :--- |
| **Dado** el arnés de Playwright, **entonces** `descubrirSoloDesarrollo` incluye todos los specs que saltan producción sin lista manual. | `test_autodescubrimiento_playwright_incluye_specs_con_skip_produccion` |
| **Dado** un cambio exclusivo en una sala (ej. `roadmap`), **entonces** `seleccionar_pruebas` genera solo los specs de esa sala y excluye salas no tocadas (M1). | `test_seleccion_playwright_sala_especifica` |
| **Dado** un cambio en layout o componentes compartidos de frontend, **entonces** `seleccionar_pruebas` devuelve `tests/` íntegro (M2). | `test_seleccion_playwright_layout_compartido_corre_todo` |
| **Dado** un cambio confinado a backend puro o gobernanza, **entonces** `seleccionar_pruebas` genera cadena vacía para omitir el job en CI (M3). | `test_seleccion_playwright_gobernanza_sin_ui_omite_job` |
| **Dado** una corrida hacia `main` o modo completo, **entonces** siempre se devuelve `tests/`. | `test_seleccion_playwright_modo_completo_corre_todo` |
| **Dado** el universo de pruebas de interfaz, **entonces** ninguna especificación queda sin proyecto en CI (M4). | `test_invariante_descubrimiento_sin_falsos_negativos` |

Las pruebas residen en `tests/test_ci30_playwright_por_salas.py`, `tests/test_ci16_pruebas_sin_proyecto.py` y `tests/test_seleccionar_pruebas.py`.
