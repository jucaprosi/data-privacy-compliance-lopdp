**Cambio en `roadmap_tasks`** (misma migración):

- Índice único parcial `ux_roadmap_tasks_hallazgo (hallazgo_id) WHERE hallazgo_id IS NOT NULL`: un hallazgo genera a lo sumo una tarea.

## 2. API

Router `api/routers/roadmaps_hallazgos.py`, prefijo `/roadmaps`, `AUTO_REGISTRO = True`.

| Método y ruta | Roles | Entrada | Respuesta |
| :--- | :--- | :--- | :--- |
| `GET /roadmaps/hallazgos?estado=&origen=` | `implementador`, `coordinador`, `dpo`, `admin_organizacion` | filtros opcionales, valores de los `CHECK` | `200 {"hallazgos": [Hallazgo]}` ordenados por severidad (`critica`, `alta`, `media`) y `creado_en` descendente |
| `POST /roadmaps/hallazgos/desde-diagnostico` | `implementador` | sin cuerpo | `201 {"creados": int, "existentes": int}` |
| `POST /roadmaps/{roadmap_id}/hallazgos/convertir` | `implementador` | `{"hallazgo_ids": [str] (1..100), "wave_id": str}` | `201 {"tareas": [{"tarea_id": str, "hallazgo_id": str}], "omitidos": [{"hallazgo_id": str, "motivo": "YA_CONVERTIDO"}]}` |

`Hallazgo` = `{id, origen, origen_ref, control_ref, dimension, severidad, titulo, descripcion, estado, tarea_id, creado_en}` (`tarea_id` es `null` si no tiene tarea).

Errores (nuevos en `app_core/errors.py` salvo los de FastAPI):

| Código HTTP | `code` | Cuándo |
| :--- | :--- | :--- |
| 403 | (dependencia de roles) | rol fuera de la tabla; el `dpo` al registrar o convertir |
| 404 | `DIAG_SIN_RESULTADO` | no hay ningún resultado sellado del diagnóstico en la organización |
| 404 | `HALLAZGO_NO_ENCONTRADO` | algún `hallazgo_id` no existe en la organización (RLS lo hace invisible) |
| 404 | `ROADMAP_NO_ENCONTRADO` | `roadmap_id` o `wave_id` no existen en la organización, o la ola no pertenece a la hoja de ruta |
| 409 | `HALLAZGO_CERRADO` | algún hallazgo pedido está `cerrado` |
| 422 | (FastAPI) | lista vacía, más de 100 ids, campos ausentes |

Ninguna ruta acepta `tenant_id`, `creado_por`, `estado` ni fechas en el cuerpo.

## 3. Reglas

- **R1 · Compuerta única.** `features/roadmap/roadmap_service.py#RM-21` expone `registrar_hallazgo(session, tenant_id, user_id, origen, origen_ref, severidad, titulo, control_ref=None, dimension=None, descripcion=None) -> (hallazgo_id, creado: bool)` y `crear_tareas_desde_hallazgos(session, tenant_id, user_id, roadmap_id, wave_id, hallazgo_ids) -> ResultadoConversion`. Ninguna otra sala inserta en `hallazgos` ni crea tareas correctoras.
- **R2 · Productor diagnóstico.** Se toma el resultado sellado de mayor `secuencia` de la organización (por `diagnostico_service`). Para cada brecha con `severidad = CRITICO`, es decir `riesgo = (5 − nivel_efectivo) × criticidad ≥ 15` según `features/diagnostico/services/dimensiones_sgpdp.py`, se registra un hallazgo `origen = 'diagnostico'`, `severidad = 'critica'`, `control_ref = brecha.control`, `dimension = brecha.dimension_id`. Las brechas `ALTO` no se registran en esta tarea.
- **R3 · Clave de origen.** Diagnóstico: `origen_ref = "<resultado_id>:P<pregunta_id>"`. Registrar dos veces el mismo resultado no crea filas nuevas (`existentes` cuenta las ya presentes).
- **R4 · Conversión.** Para cada hallazgo `abierto` sin tarea: se crea una tarea en `wave_id` con `title = titulo`, `description = descripcion`, `control_ref`, `dimension` (si el hallazgo no tiene, `D01`), `priority = severidad`, `status = 'pendiente'`, `hallazgo_id = id`; el hallazgo pasa a `en_tratamiento`. Un hallazgo que ya tiene tarea va a `omitidos` y no crea otra. Todo en una transacción: o se convierten todos los válidos, o ninguno.
- **R5 · Transiciones.** `abierto → en_tratamiento` (al convertir). `en_tratamiento → cerrado` cuando todas sus tareas están `completada`; la implementación del cierre automático queda como decisión abierta (no la hace esta tarea). No hay transición de vuelta.
- **R6 · Auditoría.** `registrar_evento(entity_type='hallazgo', action='registrado' | 'convertido', payload={origen, origen_ref, tarea_id?})` por cada hallazgo creado o convertido.
- **R7 · Invariante.** `∀ h ∈ hallazgos : h.estado ≠ 'abierto' ⇒ ∃! t ∈ roadmap_tasks : t.hallazgo_id = h.id` (`INV_LOPDP_SINGLE_ACTION_PLAN`).
