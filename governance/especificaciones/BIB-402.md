# BIB-402 · Documentos de la organización vinculados a tratamientos, controles y tareas; aviso al cambiar un tratamiento
`¤sdd` `¤rat` `¤hallazgos`

## 1. Datos

Migración `20261103_biblioteca_vinculos`: `biblioteca_vinculos (id, tenant_id, documento_id, tipo VARCHAR(12) CHECK (tipo IN ('tratamiento','control','tarea')), ref VARCHAR(120), estado VARCHAR(10) CHECK (estado IN ('vigente','revisar')), creado_por, creado_en)`, `UNIQUE (tenant_id, documento_id, tipo, ref)`. RLS ENABLE y FORCE; `lopdp_app`: SELECT, INSERT, UPDATE (estado).

## 2. API

| Método y ruta | Roles | Entrada | Respuesta |
| :--- | :--- | :--- | :--- |
| `GET/PUT /biblioteca/documentos/{id}/vinculos` | escriben `implementador`, `coordinador`; leen todos | `{"tratamientos": [id], "controles": ["P.."], "tareas": [id]}` | `200 {vinculos: [...]}` (reemplaza el conjunto) |

| Código HTTP | `code` | Cuándo |
| :--- | :--- | :--- |
| 403 | (dependencia de roles) | rol fuera de la tabla |
| 422 | `VINCULO_REF_INEXISTENTE` | tratamiento, control o tarea inexistente en la organización |

## 3. Reglas

- **R1 · Aprobación ⇒ evidencia.** Al aprobar (BIB-301) un documento con vínculo `tarea`: `roadmap_service.adjuntar_evidencia(tarea, sha256 del documento)`; el estado de la tarea no cambia (`INV_LOPDP_EVIDENCE_FOUR_EYES`).
- **R2 · Cambio de tratamiento.** `version(tratamiento) cambia ∨ baja ⇒ ∀ v ∈ vinculos(tipo='tratamiento', ref=t) : v.estado := 'revisar'` y `registrar_hallazgo(origen='rat', origen_ref=f"{t}:documento:{documento_id}", severidad='media')`.
- **R3 · Referencias.** Se validan por `rat_service`, catálogo P1–P80 y `roadmap_service`.

## 4. Interfaz

Ficha del documento: panel «Vínculos» con tres listas y distintivo «Revisar» cuando aplica; en el RAT, pestaña «Documentos que lo usan».
