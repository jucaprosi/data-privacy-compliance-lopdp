# RM-22 · Vistas de lista, tablero y cronograma
`¤sdd` `¤roadmap` `¤frontend-ide`

## 1. Datos

Sin datos persistentes. Lee las tareas de `/roadmaps` (`roadmap_tasks`: `status ∈ {pendiente, en_progreso, completada, bloqueada}`, `priority`, `start_date`, `end_date`, `hallazgo_id` de RM-21) y los hallazgos de `GET /roadmaps/hallazgos`.

## 2. API

Sin API nueva.

## 3. Reglas

- **R1 · Una fuente.** Las tres vistas renderizan la misma lista en memoria; cambiar de vista no vuelve a pedir datos.
- **R2 · Tablero.** Cuatro columnas en el orden de `status`; arrastrar una tarjeta llama al endpoint de cambio de estado existente y, si falla, la tarjeta vuelve.
- **R3 · Cronograma.** Una barra por tarea con `start_date` y `end_date`; sin fechas, la tarea aparece en una lista «Sin fecha» bajo el cronograma.
- **R4 · Vencidas.** Filtro `vencidas` = `status ≠ completada ∧ end_date < hoy` (Guayaquil); el contador del filtro coincide con el del tablero de FE-24.
- **R5 · Origen.** La tarjeta muestra «Origen: <origen del hallazgo>» cuando `hallazgo_id` no es nulo; el enlace abre el hallazgo.

## 4. Interfaz

Selector de vista (lista, tablero, cronograma) persistente en `sessionStorage`; filtro de vencidas; tarjeta con prioridad, responsable, fecha fin y origen.

## 5. Aceptación

| Escenario | Prueba |
| :--- | :--- |
| **Dado** 5 tareas simuladas, **cuando** se cambia de lista a tablero y a cronograma, **entonces** las 5 aparecen en cada vista y no hay nueva petición a `/roadmaps`. | `roadmap/vistas.spec.ts › una fuente` |
| **Dado** 2 tareas con fin ayer, **cuando** se activa «Vencidas», **entonces** se ven 2. | `roadmap/vistas.spec.ts › vencidas` |
| **Dado** una tarea con `hallazgo_id`, **entonces** su tarjeta muestra «Origen: diagnóstico». | `roadmap/vistas.spec.ts › origen` |
