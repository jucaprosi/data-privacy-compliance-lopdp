# FE-22 · Navegación por nueve menús
`¤sdd` `¤navegacion-menus` `¤frontend-ide`

## 1. Datos

Sin datos persistentes. Contrato de tipos en `frontend/src/components/layout/menus/base.ts`:

```ts
export type MenuId =
  | "inicio" | "diagnostico" | "inventario" | "biblioteca" | "operacion"
  | "riesgos_auditoria" | "dpo" | "conocimiento" | "configuracion";

export interface Menu { id: MenuId; nombre: string; orden: number }

export interface Submenu {
  vista: VistaActiva;          // la vista que monta dashboard/page.tsx
  menu: MenuId;
  nombre: string;
  subtitulo: string;
  orden: number;               // orden dentro de su menú
}
```

`menus/index.ts` exporta `SUBMENUS: Submenu[]` = concatenación de `base.ts` y de cada `menus/<ID>.ts`.

## 2. API

Sin API nueva. Los contadores por submenú solo usan endpoints que ya existen; si un endpoint falla, el submenú se muestra sin contador.

## 3. Reglas

- **R1 · Menús fijos.** Orden: Inicio, Diagnóstico, Inventario, Biblioteca, Operación, Riesgos y auditoría, DPO, Conocimiento, Configuración.
- **R2 · Reubicación completa.** Cada `VistaActiva` LOPDP actual pertenece exactamente a un menú:

| Vista | Menú | Nombre del submenú |
| :--- | :--- | :--- |
| `dashboard` | Inicio | Tablero de la organización |
| `diagnostico` | Diagnóstico | Assessment |
| `reportes` | Diagnóstico | Reporte |
| `roadmap` | Diagnóstico | Hoja de ruta |
| `rat` | Inventario | Tratamientos (RAT) |
| `terceros` | Inventario | Encargados y terceros |
| `evidencias` | Biblioteca | Evidencias |
| `arco` | Operación | Solicitudes de titulares |
| `incidentes` | Operación | Vulneraciones |
| `riesgos` | Riesgos y auditoría | Matriz de riesgos |
| `mtge_relacional` | Riesgos y auditoría | Evaluaciones de impacto |
| `auditoria` | Riesgos y auditoría | Auditorías |
| `dpo` | DPO | Panel del DPO |
| `mitigacion_ia` | Conocimiento | Copiloto |
| `configuracion` | Configuración | Perfil de la organización |

- **R3 · Unicidad.** `∀ s₁, s₂ ∈ SUBMENUS : s₁ ≠ s₂ ⇒ s₁.vista ≠ s₂.vista`; un submenú repetido rompe la compilación de las pruebas.
- **R4 · Visibilidad.** Un submenú se muestra si su vista está montada en `pantallas/index.tsx`; un menú se muestra si tiene al menos un submenú visible. Con R2, los nueve menús tienen al menos uno.
- **R5 · NIIF.** Con la normativa NIIF 18 activa se muestra `modulosNavegacionNIIF` sin cambios y no se muestran los nueve menús.
- **R6 · Búsqueda.** `Ctrl+K` compara la consulta con `nombre`, `subtitulo` y el nombre del menú, sin distinguir mayúsculas ni tildes (normalización NFD sin diacríticos).

## 4. Interfaz

- Barra superior: los nueve menús en orden R1; el activo marcado con `aria-current="page"`.
- `MenuLateral.tsx`: submenús del menú activo en su `orden`, con contador cuando exista.
- Paleta `Ctrl+K`: resultados con «Menú › Submenú»; `Enter` abre la vista; `Esc` cierra.

## 5. Aceptación

| Escenario | Prueba |
| :--- | :--- |
| **Dado** la normativa LOPDP, **cuando** se abre el panel, **entonces** se ven los nueve menús en el orden R1. | `navegacion/menus.spec.ts › nueve menús en orden` |
| **Dado** cada fila de la tabla R2, **cuando** se abre su menú y su submenú, **entonces** se monta esa vista. Mutación: quitar una fila hace fallar la prueba. | `navegacion/menus.spec.ts › cada vista desde su menú` |
| **Dado** el menú Diagnóstico, **cuando** se escribe «evaluacion de impacto» en `Ctrl+K`, **entonces** aparece «Riesgos y auditoría › Evaluaciones de impacto» y `Enter` la abre. | `navegacion/paleta.spec.ts` |
| **Dado** la normativa NIIF 18, **entonces** no aparecen los nueve menús y sí la navegación NIIF. | `navegacion/niif.spec.ts` |
| **Dado** las 25 pruebas existentes que usan `irASala`, **entonces** siguen en verde. | suite Playwright completa |
